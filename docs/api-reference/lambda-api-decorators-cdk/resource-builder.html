ResourceBuilder

Advanced API

ResourceBuilder is the lower-level, advanced interface. Prefer LambdaApi with LambdaApiConfig for new applications. This page documents the current public methods only.

Constructor​

Constructor signature: ResourceBuilder(default_runtime=None, default_timeout=None, default_memory_size=None, default_vpc=None, default_role=None, common_layers=None, common_security_groups=None, common_environments=None, custom_runtimes=None, custom_roles=None, custom_layers=None, custom_environments=None, custom_security_groups=None, custom_vpcs=None, dynamodb_tables=None, s3_buckets=None, authorizers=None, default_authorizer=None)

Parameters:

  • default_runtime (Optional[lambda_.Runtime]) – Runtime applied when a handler has no runtime alias. Default: None.

  • default_timeout (Optional[Duration]) – Timeout applied to functions. Default: None.

  • default_memory_size (Optional[int]) – Memory size applied to functions. Default: None.

  • default_vpc, default_role – Default VPC/subnets pair and execution role. Default: None.

  • common_layers, common_security_groups, common_environments – Collections applied to every function. Default: None.

  • custom_runtimes, custom_roles, custom_layers, custom_environments, custom_security_groups, custom_vpcs – Registries resolved by configuration decorators. Default: None.

  • dynamodb_tables, s3_buckets – Resource registries used by permission decorators. Default: None.

  • authorizers (Optional[Dict[str, object]]) – REST and HTTP authorizer registry. Default: None.

  • default_authorizer (Optional[str]) – Registered authorizer used for routes without an override. Default: None.

All parameters are positional-or-keyword and default to None; None becomes an empty list/dictionary where appropriate. The builder adds the runtime aliases python3.8 through python3.14 to custom_runtimes during construction. Those built-in aliases overwrite entries with the same keys.

Example:

from lambda_api_decorators_cdk import ResourceBuilder, SourceLayout

builder = ResourceBuilder(default_memory_size=512)
builder.add_common_environment("STAGE", "prod")
builder.build(stack, rest_api.root, "lambdas", source_layout=SourceLayout.ROOT)

Build operations​

build​

build(construct, api_resource: apigateway.IResource, lambda_path: str, print_tree: bool = False, source_layout: SourceLayout = SourceLayout.ROOT, layers_path: Optional[str] = None)

Discovers decorated handlers below lambda_path, prepares layers, and creates REST resources and Lambda integrations below api_resource. print_tree=True prints the discovered graph. Invalid source_layout raises TypeError; a nonexistent or non-directory layers_path raises ValueError.

build_http​

build_http(construct, http_api: apigateway2.HttpApi, lambda_path: str, print_tree: bool = False, source_layout: SourceLayout = SourceLayout.ROOT, layers_path: Optional[str] = None)

The HTTP API counterpart of build; it adds HTTP API routes. The current mapping accepts the discovered GET, POST, PUT, and DELETE methods from the public decorator set. ANY has no HTTP mapping and raises KeyError during construction.

build_lambda_function​

build_lambda_function(construct, method: ast_helper.Method, lambda_root: Optional[Path] = None, source_layout: SourceLayout = SourceLayout.ROOT)

Creates and returns a CDK PythonFunction from one discovered method. It aggregates configuration declarations, applies common, custom, and default options, and applies DynamoDB, S3, and generic IAM declarations.

build_from_graph​

build_from_graph(construct, graph: ast_helper.Resource, api_resource: apigateway.IResource, lambda_root: Optional[Path] = None, source_layout: SourceLayout = SourceLayout.ROOT)

Emits a REST resource tree and integrations from an already-built discovery graph. This is an advanced operation normally called by build.

build_http_from_graph​

build_http_from_graph(construct, graph: ast_helper.Resource, http_api: apigateway2.HttpApi, lambda_root: Optional[Path] = None, source_layout: SourceLayout = SourceLayout.ROOT)

Emits HTTP API routes from an existing graph. It is the lower-level counterpart to build_http and has the same method mapping and source-layout behavior.
